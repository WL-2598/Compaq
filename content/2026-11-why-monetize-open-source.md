# 为什么我要让一个开源项目盈利（透明版）

上个月我把一个空仓库改名前的治理文件、许可证审计、CI 全部铺完，然后发布了第一个可运行版本。仓库叫 Compaq（康柏）——一个复古计算环境：一条命令跑起 CHIP-8 虚拟机，插件扩展，纯 Python 零依赖，旧机器也能跑。

这篇文章不求 Star，讲三件有独立价值的事：**这个项目的赚钱逻辑是什么、为什么它不会背刺开源社区、以及我在第 9 周给自己定的止损线**。

## 一、钱从哪来：永远不赚"阉割免费版"的钱

很多开源项目翻车的路径是一样的：先免费，等用户离不开了，把最好的功能挪进付费版。社区炸了，项目死了。

我反着来，规则写进了社区宪章：

1. **社区版永不闭源**（MIT），**功能只增不减**——企业版只能新增模块，绝不动社区版已有的东西；
2. 收入来自四条**正交**的线：

| 收入线 | 赚谁的钱 | 本质 |
|---|---|---|
| 赞助（¥15/50/500） | 认同项目的人 | 情感收入，季度公开账目 |
| 托管版（¥49/¥199 月费） | 不想自己运维的人 | 买便利：一键部署、每日备份、监控 |
| 企业版（离线授权） | 要 SSO/审计/等保的公司 | 买合规 |
| 课程（¥199）+ 插件抽成 15% | 学习者、插件作者 | 买时间、买生态 |

注意：**没有任何一条是"免费版缺功能"**。你白嫖社区版，永远不会缺功能。

## 二、为什么现在就要透明

因为信任是这个飞轮唯一的燃料。

- 每季度公开财务报告：收入来源、支出、结余去向；
- 单一收入来源不超过 40%，单一客户不超过 30%——防止项目变成某个人的外包；
- 收入结构里如果咨询超过 40%，说明产品化失败，砍定制、做功能。

我甚至把"停止条件"也写死了：**如果第 9 周还没有第一个付费用户，回到需求验证，而不是继续堆功能。** 止损线要在冷静的时候定，焦虑的时候只会加码。

## 三、第一周实际做了什么（可复用清单）

不是写代码，是打地基——因为地基错了，后面全是返工：

1. **商标检索**：Compaq 是惠普的商标。打算商业化就必须先改名（保留"康柏"做社区昵称），检索商标、域名、GitHub 名三项，未定名前不收款、不定价、不签合同；
2. **许可证审计**：`pip-licenses` / `scancode` 过一遍依赖，GPL/AGPL 默认禁止引入。我的选择更极端——运行时零依赖，审计恒为零风险；
3. **治理七件套**：LICENSE、CONTRIBUTING（DCO sign-off）、CODE_OF_CONDUCT、SECURITY、GOVERNANCE、社区宪章、公开路线图；
4. **自动化**：Issue/PR 模板、DCO 检查、CodeQL、Dependabot、Stale、发布流水线；
5. **赞助通道**：FUNDING.yml + 三档定价，第一天就挂出来——愿意付钱的人从第一天就在看你。

## 四、产品选择：为什么是 CHIP-8

复古计算环境听着很大，我从最小可运行内核开始：CHIP-8，1975 年的解释器，4KB 内存、64×32 单色屏。用纯 Python 实现，**没有一行第三方依赖**——意味着：

- 老旧的笔记本、树莓派、甚至 Python 3.9 的受限环境，`git clone` 后一条命令跑通；
- 许可证风险为零，供应链攻击面为零；
- 演示 ROM 用内置汇编器运行时生成，仓库里连二进制文件都没有。

"5 分钟跑通"是唯一有效的验收标准。跑不通的开源项目，讲再多愿景都是零。

## 五、你可以怎么参与

- 仓库：https://github.com/WL-2598/Compaq
- 跑一下：`python -m compaq demo`
- 写插件不用动核心代码，`plugin.json` + 三个钩子（规范在 `registry/`）
- 反对商业化的声音也欢迎——社区宪章里写了，重大决策 2/3 维护者同意 + 公示两周，你有投票权。
